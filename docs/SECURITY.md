# Security notes

## Threat model

DropLink is a small personal file server. The user explicitly selects a file, and a random token grants access to that file while the application remains open. The sender's PC remains the source of the file contents.

## Implemented controls

- 16-byte token generated by the operating system's cryptographic random generator and encoded as 32 lowercase hexadecimal characters.
- Strict token validation; recipient endpoints never accept filesystem paths.
- One share record maps to one selected file; there is no directory listing or arbitrary filesystem route.
- HTML escaping for names and Unicode-safe `Content-Disposition` headers.
- `HEAD` and single byte-range handling; streaming with a 64 KiB buffer and a concurrent-download limit.
- Browser security headers and no-store caching.
- Revocation removes the share from the token map, and the streaming loop rechecks whether a share remains active.
- No telemetry and no persistent cloud file storage.

## Public Internet use

- The embedded server uses HTTP locally. Use Caddy as an HTTPS reverse proxy for custom-domain public access; expose Caddy on TCP 80/443 and never forward DropLink's internal port directly from the router.
- Custom-domain HTTPS requires valid public DNS and inbound reachability (or a separately configured DNS challenge) for certificate issuance. Keep Windows Firewall enabled.
- Temporary public links use a zrok tunnel. Public traffic travels through the provider's network; service limits, latency and throughput may vary.
- A share token is a bearer capability, not full authentication. Anyone holding the link can download the file until it is revoked or DropLink/the tunnel stops.
- Password protection, automatic expiry, download-count limits, persistent transfer history and per-download audit logs are not implemented.
- The local HTTP URL is unencrypted. Do not use it for confidential files on untrusted networks.
- File size is checked before service and before streaming, but content could still change without the size changing. Avoid editing files while they are being shared.

## Reporting

For a private security report, do not attach confidential files. Include the app version, Windows version, reproduction steps and relevant logs with tokens, personal paths and share URLs removed.
